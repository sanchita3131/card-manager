Image — no preprocessing
OpenCV

The image is passed through unchanged. Earlier versions tried to sharpen, threshold, and deskew — but PaddleOCR is trained on natural photos (phone cameras, scanners), so preprocessing only made text harder to read.

image_processor.py
def prepare(image_path: str) -> str: # Returns the path unchanged. PaddleOCR handles its own preprocessing. return image_path
2
OCR — PaddleOCR v5 + ONNX Runtime
FREE

PaddleOCR detects text regions and reads each line. It uses two ONNX models that auto-download on first run (~30 MB total):

  • PP-OCRv5_server_det_onnx — finds where text is on the image
  • en_PP-OCRv5_mobile_rec_onnx — reads the actual characters

The engine='onnxruntime' flag eliminates the need for PaddlePaddle (the 2GB deep learning framework). ONNX Runtime is lightweight and CPU-only.

Output — list of (text, confidence, bounding_box)

3
Hybrid Extraction
OpenRouter

This is the clever part. Three systems work together to turn raw text into structured fields:

🧠 LLM — Name / Position / Company

OCR lines (with y-position hints) are sent as a prompt to OpenRouter. The LLM reads contextually — it knows "CTO" is a title, "Acme Inc." is a company, and "Jane Smith" is a name — regardless of where on the card they appear.

{ "name": "Sanchita Pathak", "position": "Senior Software Engineer", "company": "Acme Technologies Inc." }
🔎 Regex — Phone / Email

Near-perfect for these formats. The patterns handle country codes, extensions, dots, dashes, and common email domains. No LLM needed — regex is cheaper and more precise for structured patterns.

EMAIL_RE = /[\w.+\-]+@[\w\-]+\.[\w.\-]+/ PHONE_RE = /(?:\+?\d{1,3}...)?\(?\d{2,4}\)?...\d{2,9}/
⚠️ Scoring Fallback (when LLM is unavailable)

If OpenRouter is down or no API key is set, the scoring system kicks in. Every text line is scored for every field type using:

  • 150+ job keywords — CEO, Director, Engineer, etc.
  • 40+ company suffixes — Inc, LLC, Corp, GmbH, Technologies
  • Capitalization analysis — ALL-CAPS likely = company
  • Position on card — top = company, middle = name/title
  • Font size — bigger text = company name
  • Anti-patterns — "Division", "Group", "Solutions" penalized as names
🗺️ Extraction Flow (in code)

Round 0 — LLM gets all OCR lines, returns name/position/company
Round 1 — Regex sweeps ALL lines for email + phone (always runs)
Rounds 2–5 — Scoring fills whatever fields are still null (fallback)

4
Write to Google Sheets
gspread

A service account (server-to-server auth, no OAuth popup) appends a row:

value_input_option="RAW" prevents phone numbers like +1... from being interpreted as spreadsheet formulas.

Project History — Why it's built this way
  • Was: CLAHE + adaptive threshold preprocessing → destroyed text
  • Now: Raw image to PaddleOCR — it's trained on natural photos
  • Was: Fixed zones (header/body/contact) → broke on every layout
  • Now: Scoring + LLM — every line scored independently, layout-agnostic
  • Was: Pure heuristics → failed on "Consulting Division" vs names
  • Now: LLM understands semantics, heuristics fallback when offline
  • Was: PaddlePaddle dependency (2 GB) → bloated setup
  • Now: ONNX Runtime — lightweight, CPU-only, ~30 MB models
